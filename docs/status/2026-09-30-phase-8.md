# Phase 8 status — API and front end (PRD F9–F14)

Date: 2026-09-30

## What was built

**API** (`mrvsim/api`, FastAPI; `uvicorn mrvsim.api.server:app --port 8000` also serves the built front end):

- `store.py` — loads a run directory (config, manifest, summary, posterior percentiles p5/p10/p50/p90/p95, truth, states, population, observations, deterministic deployment plan); facility GeoJSON; slice tables by basin / facility type / rate bin; drill-down payload (interval vs bar, observation timeline with cloud-outs and non-detections, CMS daily aggregates, oracle truth labelled as such); attribution resolved against `REFERENCES.md` with verify flags and per-sensor unfitted blocks.
- `jobs.py` — thread-pool job registry with status polling.
- `server.py` — endpoints listed in the decision log; interactive defaults (10 facilities/stratum, 2,000 draws, R = 3); tornado computed on demand and cached; variance budget per facility as a job; validation panel data and quick-run job; Optuna optimisation job; **gap-analysis** proxy to the Anthropic API (`claude-opus-5-5`, server-side refusal fallback, run summary + slices + tornado in the system prompt, YAML policy extracted for the Apply button; credentials only from the server environment).

**Front end** (`web/`, React 18 + Vite + MapLibre + Recharts + react-markdown; `npm run build` → served by the API):

- **Map** — OSM basemap, three-state facility colouring recomputed in the browser at the user's KPI, bar, and precision; legend with counts; click → **drill-down** with the interval bar against the bar line (p5–p95, p10–p90, median, truth marker), per-sensor observation timeline (detections, non-detections, cloud-outs, wind-outs, night passes, false positives), CMS detected share, **Compute variance budget** bar chart, oracle truth under a disclosure.
- **Dashboard** — headline tiles (certified share by facilities and throughput, κ flagged red outside 0.85–0.95, median w, bias, completeness, cost per tonne and per certified MMBtu), **Compute tornado** (horizontal bars, narrowing in blue), Pareto frontier scatter (fed by the optimizer), slice tables, run provenance footer.
- **Sensors** (left panel) — on/off, coverage, surveys/taskings per year, targeting per sensor; tier badges; **Advanced**: validation-tier filter, facilities per stratum, draws, replications, seed; **Run** with job progress.
- **Optimize** — constraints and study settings, **Find frontier**, Pareto table with **load** into Sensors.
- **Gap analysis** — chat with Apply for proposed YAML; explains when the server has no credentials.
- **Attribution**, **Validation** (V1–V7 cards with status, diagnostic-only badge, compared values), **?** quick-start modal rendering `docs/QUICKSTART.md`.
- Light and dark themes from the dataviz reference palette; colour never the only encoding (labels, legends, badges).

## Verification

- Smoke test against the live server: a 252-facility, 2-replication run completed in 136 s; κ = 0.90; facilities, drill-down (410 timeline rows), attribution (27 citations, 19 flagged `verify`), validation, quick start, and a variance budget job all returned correctly; gap analysis without credentials returns 401.
- `tests/unit/test_api.py` (3 tests, one slow): health/sensors/quickstart/references; run → summary → facilities → drill-down → attribution → validation → budget job → gap-analysis error path; 404s.
- Front end builds cleanly (1,534 kB bundle; MapLibre dominates). Unit suite: 128 tests passing.

## Open questions / caveats

- **PRD N3** is met only in the interactive-subsample sense (decision log item 2); a full-sample recompute at R = 20 still takes tens of minutes. Nidhi to confirm this interpretation.
- With placeholder priors and the default 0.2 % bar, essentially no facility certifies (median intensity in the synthetic population is 0.4 % with w ≈ 1); the three-state colouring and all metrics are exercised but the numbers are not meaningful until priors are fitted.
- The gap-analysis chat was not exercised against the live Anthropic API in this environment (no credentials); the request shape follows the current SDK documentation and the error paths are tested.
- Bundle size could be cut with code-splitting; not done.

## Blocked

- Nothing. All eight phases have a first implementation. The programme-level blockers are fitted priors (Q1), transcribed validation targets, blind-release tables for sensor fits, and the N3 decision.
