- **`mrvsim.io`** (PRD N4):
  - `seeds.py` — `SeedTree(master_seed)` hands out PCG64 generators by named path; paths are BLAKE2b-hashed into `SeedSequence` spawn keys, so streams are order-independent and a new stream added later cannot perturb existing ones. `integer_seed()` for PyMC/Optuna.
  - `config.py` — `RunConfig` (seed required, unknown sections rejected), `load_config`, `canonical_yaml`, `config_hash` (SHA-256 of sorted YAML).
  - `run.py` — `RunContext` creates `runs/<id>/` with `config.yaml`, `manifest.json` (seed, config hash, git SHA + dirty flag, dependency versions, platform, per-stage and total elapsed time, status/error), and byte-stable writers `save_array/save_json/save_frame`. `compare_run_dirs` byte-compares two runs.
- **`configs/default.yaml`** with the top-level sections; stage sections are skeletal until their phase.

## Open questions

- **Q4 resolved.** LDAR-Sim v4.2.4 has no satellite scheduling at all: `Deployment_Types.ORBIT` is a dead constant; only `mobile` and `stationary` are implemented; the README's `orbit_predictor` line is stale. The legacy V3 branch had `orbit_crew.py` (TLE propagation via `orbit_predictor`, 15-minute position steps, bounding-box swath polygons, daily gating). v4's wind-dependent METEC POD sensor is fully commented out.
- **Q6 added (needs Nidhi's decision before Phase 3).** The "fork LDAR-Sim v4 as the simulation engine" decision (PRD §7.5, TDD §1) assumed a reusable detection and scheduling engine. What v4 provides is a daily-timestep, agent-based, per-site loop with no satellite module and a stubbed weather-dependent POD; the TDD asks for hourly, vectorised, per-facility numpy arrays with no per-facility Python loops (CLAUDE.md conventions, TDD §10). The decision is not overturned here. Proposed resolution, to be logged if accepted: keep LDAR-Sim vendored as the reference implementation and V2-style cross-check, reuse its ERA5 downloader/concatenator, daylight calculator, and parameter naming conventions, and implement the MRVSim hot path natively. Phases 1–2 do not depend on this choice.
